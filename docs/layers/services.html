Auth 服务知识点

JWTManager · Access + Refresh 双 Token

services/auth/jwt.go
  • Access Token：短期 30min，携带 user_id / role / jti。
  • Refresh Token：长期 7d，不带 role——刷新时重新查角色，避免角色变更后 Refresh 仍带旧角色。
  • jti：uuid.NewString()，唯一 ID 用于吊销。
  • 签名：HS256，Parse 强制 SigningMethodHMAC，拒绝 alg:none。
  • TTL 暴露：AccessTTL() / RefreshTTL() 给 Redis 设过期时使用。

password · bcrypt 密码哈希

services/auth/password.go

用 bcrypt 做密码哈希，自带盐与可调成本因子，抗暴力破解与彩虹表。

apikey · 服务端只存 SHA256

services/auth/apikey.go

APIKey 签发后只在 DB 存 SHA256(key)；校验时对入参做 SHA256 比对，DB 泄露也无法还原原 Key。

rbac.go · 角色权限定义

services/auth/rbac.go

权限命名 resource:action（kv:get / kv:put / rag:ingest），与网关 middleware/rbac.go 对齐。

store.go · 用户持久化

services/auth/store.go · client.go · handler.go

用户表存储 + Gateway 调用 Auth 的 HTTP client（注册/登录/刷新/登出/apikey Handler）。

RAG 服务 · 检索增强生成全链路

RAG 是本层最复杂的服务，从文档入库到流式问答一条龙。流程：ingest → chunker → embedding → hnsw_index → retrieve → rerank → llm → chat(SSE)。

入库 (rag:ingest): Document ──▶ chunker (分块) ──▶ embedding (向量化) ──▶ hnsw_index.Add() ──▶ store 查询 (rag:query): Query ──▶ embedding ──▶ hnsw_index.TopK(k) ──▶ retrieve (取 chunk) ──▶ rerank │ ▼ llm (prompt 拼装) │ ▼ chat (SSE 流式输出)

HNSWIndex · 分层小世界图

services/rag/hnsw_index.go

近似最近邻搜索（ANN）的工业级算法。本项目实现了一个简化版 HNSW，接口与暴力 SideIndex 兼容，便于在 N 增长时无缝切换。

  • 参数：m = 16（每层最大邻居数）、ml = 1/log(16)（层高分布系数）。
  • 随机层：randomLayer() 以 0.5 概率递增，封顶 8 层。
  • 插入 Add()：从顶层 greedyClosest 下降 → 在目标层 searchLayer(ef=m*2) 选邻居 → 双向连边。
  • 查询 TopK()：顶层贪心下降 → 底层 searchLayerLocked(ef=k*4) 取候选 → 返回 TopK Hit（按余弦相似度排序）。
  • searchLayer：候选集 + 已访问集合，ef 控制精度，超限时按相似度裁剪。
  • 相似度：cosine(query, vec) 余弦相似度。
  • 持久化：SaveSnapshot / SaveSnapshotPrefix / MergeSnapshot，JSON 存向量。
  • 按前缀清空：ClearByPrefix 支持 Collection 级删除。

VectorIndex 抽象 + SideIndex

vector_index.go

VectorIndex 接口抽象了 HNSW 与暴力 SideIndex，NewVectorIndex(dim, "hnsw") 按环境变量 RAG_INDEX_TYPE 选择实现。

chunker / embedding / rerank / llm

chunker.go · embedding.go · rerank.go · llm.go
  • chunker：文档分块（按字符/段落滑窗）。
  • embedding：文本 → 向量，封装 embedding 模型 API。
  • rerank：对 TopK 候选重排，提升相关性。
  • llm：拼装 prompt 调大模型，返回生成文本。

retrieve / ingest / chat / store

retrieve.go · ingest.go · chat.go · store.go · eval.go
  • retrieve：从向量库取相关 chunk。
  • ingest：入库主流程，串起 chunker → embedding → index。
  • chat：多轮对话 + 知识问答，SSE 流式输出。
  • store：文档与向量索引存储层。
  • eval：检索质量评测，eval_test.go。
