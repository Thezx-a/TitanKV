总览/可观测性

Observability · 横切所有层

可观测性栈不是独立的一层，而是横切所有层：每个服务暴露 /metrics 给 Prometheus 抓取， Grafana 做可视化，Jaeger 做分布式追踪，Redis 兼任限流与 jti 黑名单。一键 make docker-up 拉起。

Prometheus Grafana :3001 Jaeger :16686 Redis /metrics 分布式追踪

可观测性三支柱

┌────────────────────────────────────────────────────────────────┐ │ Metrics（指标） │ Tracing（追踪） │ Logging（日志） │ │ Prometheus 抓 /metrics │ Jaeger 跨服务关联 │ 结构化日志 + RequestID │ │ Grafana 可视化 │ gateway→service→storage │ 贯穿洋葱中间件链 │ └────────────────────────────────────────────────────────────────┘ ▲ │ 横切 ┌──────────────────┼────────────────────────┐ ▼ ▼ ▼ Go 微服务 Gin 网关 C++ minikv_server (prometheus client) (metrics.GinMiddleware) (原生指标暴露)

核心组件知识点

Prometheus · 指标抓取

deploy/dev/prometheus.yml · services/observability/metrics.go
  • 抓取目标：各服务的 /metrics 端点，prometheus.yml 配置 scrape_configs。
  • 指标暴露：Go 服务用 prometheus client，services/observability/metrics.go 定义业务指标。
  • HTTP 中间件：pkg/metrics.GinMiddleware("gateway") 自动记录请求计数 / 延迟分布。
  • 注册路由：metrics.RegisterRoutes(r) 暴露 /metrics 给 Prometheus。

Grafana · 可视化仪表盘

deploy/dev/docker-compose.yml

以 Prometheus 为数据源，构建请求 QPS / 延迟分位 / 错误率 / 业务规模等仪表盘。默认 http://localhost:3001。

Jaeger · 分布式链路追踪

deploy/dev/docker-compose.yml · middleware/request_id.go

跨网关 → 微服务 → 存储引擎关联一次请求的全链路。X-Request-ID 由网关生成，透传给后端，Jaeger UI 默认 http://localhost:16686。

Redis · 限流 + jti 黑名单

middleware/ratelimit.go · middleware/auth.go
  • 限流：令牌桶 burst=100, sustained=10/s，Redis 故障时降级为无限制。
  • jti 黑名单：登出写入 revoked:jti:<id>，TTL = token 剩余有效期。

Observability 服务 · 聚合与采集

services/observability/
  • metrics.go：业务指标定义与暴露。
  • scraper.go：周期采集其他服务指标，聚合展示。
  • handler.go：HTTP 接口。
  • cmd/main.go：服务入口，默认 :8084。

一键拉起本地栈

# 拉起 Postgres / Redis / etcd / Jaeger / Prometheus / Grafana
make docker-up

# 默认端口
#   Grafana      http://localhost:3001
#   Jaeger UI    http://localhost:16686
#   Prometheus   http://localhost:9090
#   Redis        localhost:6379
#   Postgres     localhost:5432
#   etcd         localhost:2379

make docker-down   # 关闭
