总览/网关层

API Gateway · Go + Gin

Gin 网关是请求进入业务域的第一道关卡：用洋葱模型串起 RequestID/Logger/Recover/RateLimit/Auth/RBAC， 再按前缀反向代理到各微服务。它从环境变量读配置，Redis 不可用时降级为无限制。

Go 1.23 Gin 洋葱中间件 JWT + APIKey RBAC Redis 限流 优雅停机

洋葱模型中间件链

中间件按注册顺序包裹，外层先执行 before、内层先执行 after。顺序很关键：Recover 必须在 Logger 之后（Logger 才能记到 panic），Auth 必须在 RBAC 之前（先识别身份再判权限）。

请求 ──▶ RequestID ──▶ Logger ──▶ Recover ──▶ RateLimit ──▶ Auth ──▶ RBAC ──▶ Handler │ │ ▼ ▼ 解析 JWT/APIKey 检查角色权限 (失败 401) (失败 403) 内层 Handler 处理完 → 按洋葱倒序回弹 → RBAC.after → Auth.after → RateLimit.after → ... → RequestID.after 全程同一个 goroutine，RequestID 贯穿日志与追踪。

核心组件知识点

router.go · 路由注册与反向代理映射

gateway/router.go

所有路由与中间件链在此编排，环境变量驱动配置。

  • Config：从环境变量读 GATEWAY_ADDR / JWT_SECRET / REDIS_ADDR / *_SERVICE_URL，getenv() 带默认值兜底。
  • 中间件链：gin.Recovery() + metrics.GinMiddleware + RequestID→Logger→Recover→RateLimit。
  • 无鉴权：GET /ping、GET /healthz、POST /api/auth/{register,login}。
  • 鉴权组：POST /api/auth/{refresh,logout,apikey}，apikey 还需 apikey:issue 权限。
  • 反向代理 map：/api/data → :8081、/api/meta → :8083、/api/observability → :8084、/api/rag → :8085。
  • RBAC 分流：data/meta/observability 按方法映射 KV 权限；rag 区分 retrieve/chat=rag:query 与其他写=rag:ingest。
  • 优雅停机：SIGINT/SIGTERM → srv.Shutdown(5s)。

Auth · JWT + APIKey 双轨

gateway/middleware/auth.go

识别「你是谁」：优先 Bearer JWT，其次 X-API-Key。失败统一 401。

// 优先级
1) Authorization: Bearer <jwt>   → parseJWT → 检查 jti 黑名单
2) X-API-Key: <key>              → 调 Auth 服务 VerifyAPIKey
3) 都没有 → 401 unauthorized
  • alg:none 防御：parseJWT 强制 SigningMethodHMAC，拒绝 alg:none 伪造攻击。
  • jti 黑名单：登出时把 jti 写入 Redis revoked:jti:<id>，TTL = token 剩余有效期。
  • Redis 故障放行：isRevoked 查询失败时返回 false，避免 Redis 抖动阻断全部请求。
  • 上下文注入：c.Set("user_id" / "role" / "auth_method") 给后续中间件。
  • APIKey 哈希：HashAPIKey 服务端只存 SHA256，DB 泄露不暴露原 Key。

RBAC · 角色权限矩阵

gateway/middleware/rbac.go

判断「你能干啥」：基于角色的权限控制，权限命名规范 resource:action。

  • 失败 403：返回 required 与当前 role，便于排查。
  • 细粒度方法映射：data 路由组按 HTTP 方法映射 GET=kv:get / POST|PUT=kv:put / DELETE=kv:delete。

ReverseProxy · 前缀路由 + 身份注入

gateway/handler/proxy.go

基于 httputil.NewSingleHostReverseProxy 封装，按前缀选目标，并注入身份头。

  • targets map：prefix → *url.URL，启动时解析一次。
  • 身份透传：转发前注入 X-User-ID / X-Role / X-Request-ID，后端服务拿到身份无需再解 JWT。
  • 404 兜底：无匹配前缀返回 no upstream for path。
  • 扩展：生产可换为基于 etcd 的动态服务发现。

其余中间件

gateway/middleware/
  • RequestID：每请求生成唯一 ID，写入 X-Request-ID 头与日志，串联全链路追踪。
  • Logger：结构化记录请求方法/路径/状态/耗时。
  • Recover：捕获 panic，记日志后返回 500，不让进程崩。
  • RateLimit：Redis 令牌桶，burst=100, sustained=10/s；Redis 不可用时直接不启用（降级）。
  • shard.go：分片逻辑占位，配合分布式层使用。
