核心知识点

apiFetch · 统一请求封装

web/lib/api.ts

所有后端请求都走 apiFetch，集中处理鉴权、错误、401 跳登录。

  • API_BASE：从 NEXT_PUBLIC_API_BASE 注入浏览器端，默认 http://localhost:8080。
  • 自动 Bearer：浏览器读 titan_token cookie，自动注入 Authorization: Bearer <token>。
  • query 拼接：withQuery() 用 URLSearchParams 把 query 对象拼到 URL。
  • JSON 自动解析：按 content-type 判断是否 JSON；204 返回 undefined。
  • HttpError：业务错误类，承载 status / code / message / details。
  • 401 处理：清 cookie + 跳 /login（仅浏览器端，当前不在登录页时）。
  • 便捷方法：api.get / post / put / delete。
  • credentials: include：跨域时携带 cookie。

middleware.ts · 路由级鉴权

web/middleware.ts

Next.js middleware 在请求到达页面前校验 titan_token cookie，无 token 重定向到 /login。保护 /dashboard/*。

login · 登录写 cookie

web/app/login/page.tsx

表单提交 → 调 /api/auth/login → 把 JWT 写入 titan_token cookie → 跳 dashboard。

dashboard/layout · 左导航布局

web/app/dashboard/layout.tsx

所有 dashboard 子页共享布局：左侧 nav.tsx 导航 + 右侧内容区。

rag.ts · SSE 流式问答

web/lib/rag.ts · [col]/chat/page.tsx

RAG chat 走 Server-Sent Events：后端流式输出 token，前端逐字渲染。rag.ts 封装 SSE 客户端。

components · 可复用组件

web/components/
  • live-metrics.tsx：实时指标展示（SSE / 轮询）。
  • metrics-card.tsx：单指标卡片。
  • nav.tsx：侧边导航 + 当前页高亮。
  • providers.tsx：全局 Provider（TanStack QueryClient 等）。

Dashboard 各页

web/app/dashboard/
  • cluster/page.tsx：集群节点拓扑展示。
  • collections/page.tsx：Collection 列表与管理。
  • data/page.tsx：KV 数据浏览（TanStack Query 获取）。
  • rag/page.tsx：RAG 文档列表，[col]/chat 子路由聊天。
  • users/page.tsx：用户管理（需 user:manage 权限）。
